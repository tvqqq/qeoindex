# QEO-232 Daily OHLCV Provenance Contract Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the approved QEO-232 provenance design into source-level guardrails that make the future QEO-233 additive migration fail closed if it violates the exact Daily provenance identity, rollback, ABI, or no-reclaim constraints.

**Architecture:** QEO-232 does not ship a database migration. It adds a reusable SQL contract validator, a focused characterization/guardrail test suite, and a dedicated GitHub Actions workflow. The tests lock the current Daily provenance-sensitive writer/reader inventory and the 10-field grouped-RPC ABI, then automatically validate any future QEO-233 provenance migration files when they appear. QEO-233 remains responsible for the additive registry/reference schema, dual-write compatibility, and bounded backfill; QEO-234 remains responsible for dropping long inline fields and physical reclamation.

**Tech Stack:** TypeScript, Node.js 24 built-in test runner, GitHub Actions, PostgreSQL/Supabase migration source contracts.

**Spec:** `docs/superpowers/specs/2026-09-15-qeo-232-daily-ohlcv-provenance-design.md`

## Global Constraints

- Do not create or apply a QEO-233 production migration in QEO-232.
- Do not modify production Supabase data, run backfill, prune Daily rows, drop provenance columns, rewrite `market_ohlcv_history`, or run `VACUUM FULL`.
- Keep `market_ohlcv_history` as the canonical completed-Daily fact store; do not merge it with intraday storage.
- Version-1 provenance identity is exact byte-for-byte `(provider, provider_detail, source_url)` with explicit `identity_version = 1` semantics.
- Keep `provider` and `fetched_at` inline; QEO-234 may later remove only `provider_detail` and `source_url` after QEO-233 gates pass.
- `market_ohlcv_history.provenance_id` must remain nullable in the additive QEO-233 migration phase and use a restrictive FK; no cascading fact deletion is allowed.
- Preserve the grouped Daily RPC positional ABI exactly as width 10: `[bar_time, open, high, low, close, volume, provider, provider_detail, source_url, fetched_at]`.
- QEO-232 tests use `.cases.ts`, not a top-level `.test.ts`, so they remain outside `tests/test-contracts.json` and are owned by their focused workflow.
- Under the QeoIndex ChatGPT Web policy, do not run shell/npm/pnpm commands locally. The commands below are the exact GitHub Actions or human/Codex verification commands; ChatGPT Web execution must use GitHub Actions for RED/GREEN evidence.

```ts
const SAFE_ADDITIVE_SQL = `
begin;
create table public.market_ohlcv_provenance (
  id bigint generated by default as identity primary key,
  identity_version smallint not null default 1,
  provider text not null,
  provider_detail text not null,
  source_url text not null,
  created_at timestamptz not null default now(),
  unique (identity_version, provider, provider_detail, source_url),
  check (identity_version = 1)
);
alter table public.market_ohlcv_history
  add column provenance_id bigint null;
alter table public.market_ohlcv_history
  add constraint market_ohlcv_history_provenance_id_fkey
  foreign key (provenance_id)
  references public.market_ohlcv_provenance(id)
  on delete restrict;
create or replace function public.qeo_market_ohlcv_recent_grouped(
  p_tickers text[],
  p_limit integer default 260
)
returns table (ticker text, rows jsonb)
language sql
stable
as $$
  select q.ticker,
    jsonb_agg(jsonb_build_array(
      h.bar_time, h.open, h.high, h.low, h.close, h.volume,
      h.provider, h.provider_detail, h.source_url, h.fetched_at
    ) order by h.bar_time)
  from requested q
  join hydrated_daily_compat h on h.ticker = q.ticker
  group by q.ticker;
$$;
commit;
`

    `${SAFE_ADDITIVE_SQL}\nselect * from public.chart_ohlcv_provenance_batches;`,
    `${SAFE_ADDITIVE_SQL}\nvacuum full public.market_ohlcv_history;`,
    `${SAFE_ADDITIVE_SQL}\ndelete from public.market_ohlcv_history;`,
```

- [ ] **Step 2: Implement the positive schema assertions.**

The validator must require the approved additive shape:

```ts
export function assertQeo232DailyProvenanceSchema(sql: string) {
  const source = compactSql(sql)

  assert.match(source, /create table(?: if not exists)? public\.market_ohlcv_provenance\s*\(/i)
  assert.match(source, /id bigint generated by default as identity primary key/i)
  assert.match(source, /identity_version smallint not null default 1/i)
  assert.match(source, /provider text not null/i)
  assert.match(source, /provider_detail text not null/i)
  assert.match(source, /source_url text not null/i)
  assert.match(source, /check\s*\(\s*identity_version\s*=\s*1\s*\)/i)
  assert.match(
    source,
    /unique\s*\(\s*identity_version\s*,\s*provider\s*,\s*provider_detail\s*,\s*source_url\s*\)/i,
  )

  assert.match(
    source,
    /alter table public\.market_ohlcv_history[\s\S]*?add column(?: if not exists)? provenance_id bigint(?: null)?/i,
  )
  assert.match(
    source,
    /foreign key\s*\(\s*provenance_id\s*\)[\s\S]*?references public\.market_ohlcv_provenance\s*\(\s*id\s*\)[\s\S]*?on delete restrict/i,
  )

  assert.match(source, /create or replace function public\.qeo_market_ohlcv_recent_grouped/i)
  assert.match(
    source,
    /jsonb_build_array\([\s\S]*?h\.bar_time\s*,\s*h\.open\s*,\s*h\.high\s*,\s*h\.low\s*,\s*h\.close\s*,\s*h\.volume\s*,\s*h\.provider\s*,\s*h\.provider_detail\s*,\s*h\.source_url\s*,\s*h\.fetched_at[\s\S]*?\)/i,
  )
```

The helper validates migration source shape only. Runtime equality/backfill correctness remains QEO-233 scope.

- [ ] **Step 3: Implement the destructive/semantic rejection assertions.**

```ts
  for (const column of ["provider", "provider_detail", "source_url", "fetched_at"]) {
    assert.doesNotMatch(
      source,
      new RegExp(`drop\\s+column(?:\\s+if\\s+exists)?\\s+${column}\\b`, "i"),

  }

  assert.doesNotMatch(source, /chart_ohlcv_provenance_batches/i)
  assert.doesNotMatch(source, /delete from public\.market_ohlcv_history/i)
  assert.doesNotMatch(source, /truncate(?: table)? public\.market_ohlcv_history/i)
  assert.doesNotMatch(source, /vacuum\s+full/i)
  assert.doesNotMatch(
    source,
    /create table[\s\S]*?as\s+select[\s\S]*?from public\.market_ohlcv_history/i,
  )
}
```

QEO-233 must remain additive, so even `provider_detail` and `source_url` cannot be dropped there; QEO-234 owns those removals. `provider` and `fetched_at` are explicitly retained by the approved design.
