# Market board data and performance model

Last updated: 2026-10-06

## Server bootstrap

The authenticated `/board` page verifies the Supabase server session before loading board data. The server then assembles one initial board model from bounded sources in parallel:

- Supabase orderbook snapshots for persisted reference/session/orderbook data.
- Broker batch quotes for current quote fields.
- The shared 5-minute intraday snapshot cache for mini-chart history.
- DNSE's current VN30 basket-membership endpoint, validated as exactly 30 unique symbols and cached for six hours. Provider time is retained as `asOf`; failed fetches/cache reads leave membership unavailable and do not fail board SSR.

The SSR model is cached through the QeoIndex UI cache with a short session-aware TTL. This lets the first render contain usable prices and chart history before the browser WebSocket becomes live. The cache namespace is versioned so a release that changes intraday completeness semantics can invalidate stale board payloads immediately.

When SSR already provides usable multi-point history for at least 95% of the canonical universe, the browser does not immediately call `/api/market/intraday` again on first mount. A session rollover still increments the reload key and forces a fresh browser history bootstrap.

## Filter CP

`Filter CP` is injected beside the existing `Tất cả` and `Top movers` controls without duplicating the market-board realtime store. It filters only the current canonical board universe (currently capped at Top 200). The filter editor may group raw sector labels into its six selection buckets, while the priceboard renders every distinct raw `kfspSector` label as its own industry column.

Supported criteria:

- exchange: HOSE / HNX / UPCOM, multi-select;
- minimum stock price in VND;
- minimum canonical 50-session average volume (`averageVolume50d`) in shares per session;
- raw canonical/KFSP sector labels selected through the filter editor's six selection buckets.

Board quotes are normalized internally in thousands of VND (for example `66.1` means `66,100 VND`). The filter helper converts those values to VND before applying the user-entered price threshold. Liquidity does **not** use the current-session matched volume: the threshold is evaluated from the canonical universe's `averageVolume50d`, so the same filter remains stable regardless of what time the user opens the board.

The KFSP sector editor follows `BOARD_SECTOR_GROUPS` in board order: `Ngân hàng`, `Chứng khoán`, `Bán lẻ`, `Bất động sản`, `Công nghiệp`, `Còn lại`. Each raw KFSP sector is assigned with `boardSectorGroupForSector`. All available sectors are selected by default. Bank and securities are mandatory; every other non-empty selection bucket must retain at least one selected raw sector. These six buckets belong only to the editor and do not combine the raw industry columns displayed by the priceboard. Saved criteria that violate the editor invariants are treated as invalid and the editor falls back to defaults.

Criteria persist per authenticated user at `user_preferences.settings.marketBoard.stockFilter`. The dedicated `/api/me/market-board-filter` route validates the payload and server-merges only the stock-filter key so unrelated preference settings survive the write. The existing `minVolumeShares` JSON key remains backward compatible, but its product meaning is now minimum 50-session average volume rather than current-session volume.

The resolved ticker list is cached in browser local storage under a per-user namespace. A cache entry is valid only when all of these identities still match:

- authenticated user ID;
- Vietnam date (`Asia/Ho_Chi_Minh`);
- canonical universe `runId`;
- deterministic hash of normalized criteria;
- every cached ticker still belongs to the current canonical universe.

Ticker membership is frozen for that valid daily cache entry. Quotes for the selected tickers remain realtime. Opening the editor and pressing `Áp dụng` recomputes membership from a fresh price snapshot while the KLTB 50-session criterion comes from the already-loaded canonical universe. If an already-filtered tab remains open across a Vietnam trading-day rollover, the market-session reset event invalidates that in-memory daily membership and re-resolves Filter CP once from a fresh quote snapshot before remounting the filtered board.

The filter shell deliberately passes only the filtered universe to the existing `LiveMarketBoard`. The board therefore derives its price `symbolList` from only those tickers, so price channels (`tick`, `top_price`, `ohlc`) and visible stock rows stay filter-scoped. Cumulative foreign frames continue updating the full canonical Top 200 through the worker feed, keeping context coverage measured against the canonical universe while Filter CP is active. The full canonical universe is passed separately for industry identities and watch-search suggestions; market-index channels remain present independently. VN30 coverage is measured against the full canonical symbol set so filtering does not change membership data.

Returning to `Tất cả` or `Top movers` is guarded by `/api/market/quotes`: broker batch quotes and one bounded canonical snapshot query run in parallel, and the transition is rejected if any requested symbol still lacks a valid quote. After a successful reconcile the shell remounts the board with the full canonical universe and clears the history seed, forcing the existing intraday bootstrap instead of treating off-filter history as fresh.

A failed persistence write never disables the locally active filter. A failed full-universe reconcile does the opposite: the app remains in Filter CP rather than expose stale full-board data.

## Intraday history cache

`modules/market/realtime/intraday-5m-service.ts` keeps the complete canonical-universe history snapshot as one cache object:

1. Vercel Runtime Cache exact session bucket.
2. Upstash Redis exact session bucket when configured.
3. Today's latest known-good snapshot from Redis/Runtime Cache; during a live session it is accepted only when generated in the current or immediately previous 5-minute bucket, while lunch-break reuse must already cover the final 11:25 morning bar for the required universe coverage.
4. Provider fan-out only when no acceptable cached snapshot exists.

The provider path tries the DNSE 5-minute chart endpoint first and falls back to Yahoo when required. Fetch concurrency remains bounded at 12 symbols.

`/api/market/intraday` follows the same stale-while-live strategy, but reuse is session-aware. During live trading, an exact current bucket remains preferred and a `latest` fallback is accepted only from the current or immediately previous 5-minute bucket. During lunch, both exact `lunch_break` and `latest` snapshots must already cover the final 11:25 morning bar for enough rows; otherwise the service falls through to provider refresh. This keeps the complete 09:15–11:25 morning chart visible while realtime ingestion is paused, then allows realtime to continue from 13:00.

Vercel runtime audit on 2026-08-21 found three 20-second timeouts across `/api/market/index-candles` and `/api/market/intraday`. The cache-first and SSR-history-reuse changes directly target the intraday portion of that failure mode.

## Market context strip

The authenticated market board displays exactly **four cards in one non-scrollable desktop row** (smaller viewports wrap cards responsively): combined **VN-Index / VN30**, **Thanh khoản HOSE**, **Mua bán nước ngoài**, and **Tác động VNINDEX**. Widths use `minmax(0,...)` so the strip never adds horizontal scrolling. Card heights are 156px on desktop. Market context stays mounted when hidden by the Bảng ngành toggle, retaining bounded live samples. All four headers have a **small, nontext pulsing dot only on verified fresh source ticks** (the visible LIVE/Chậm/Nghỉ badges were removed); the numeric and intraday series animations remain evidence-gated. Both VNINDEX and VN30 must have same-session index source timestamps to mark the combined card LIVE. HOSE liquidity uses its selected index liquidity provider timestamp; foreign trading uses a verified Finhay source timestamp or DNSE Top-200 latest foreign tick; impact only pulses for a genuinely fresh DNSE WebSocket snapshot (cached REST is never labelled LIVE). The marker checks market hours, trading-day calendar and source age (120s maximum), refreshing locally every 15 seconds without any new provider requests. A single short header sweep replays **only when the source timestamp changes**; index/cumulative/foreign/basket numeric values animate briefly **only on actual changed source-backed values**, not on every render. Current-session line charts briefly trace their newest recorded line segment and pulse the current endpoint; yesterday's comparison never animates. Impact bars retain existing smooth top/height transitions. Animation is CSS-bounded and fully suppressed by `prefers-reduced-motion`; nothing pretends to be live during lunch, EOD, holidays or stale-provider periods.

- **VN-Index / VN30**: one combined two-column summary card. It renders current index value, verified change/% change, same-session index volume and traded value, and provider-reported rising/flat/falling constituent counts when available. Index line charts and their independent DNSE 1-minute history bootstrap were deliberately removed. **Market breadth** (tăng/đứng/giảm) for both full-universe VNINDEX and VN30 is read from the existing Finhay `list_indices(window=1D)` call, now requesting `advancers,decliners,unchanged` and retaining its provider `updated_at`; this adds **no further Finhay request**. If Finhay is not authenticated or has no same-session valid counts, the board polls the existing authenticated `/api/market/indexes` cached snapshot for VPS `ot` breadth at a bounded 30s cadence, preserving real zero counts. VPS counts use the snapshot **receipt** time, not an exchange source timestamp: the tooltip distinguishes this from Finhay provider time, and pre-open/holiday VPS fallback is suppressed. Neither snapshot may overwrite DNSE live index price, change or volume. The index **level** has a smaller font (12–17px) while its **point change** is larger (12–15px); daily **percentage change** uses a larger 12px signed green/red/amber pill; a compact directional arrow icon (up/right/down or unavailable activity indicator) replaces the ambiguous leading dash before the index level while the actual point change remains signed. The full-width proportional green/yellow/red breadth bar is pinned to the **bottom of each VN-Index / VN30 summary** (with both summaries height-aligned) and sits **above** the counts. The three rising/flat/falling labels are positioned under the centers of their corresponding colored segments, smoothly tracking verified live breadth changes; narrow and zero-width portions have edge limits and minimum spacing to avoid overlap. Missing and genuine zero counts remain explicitly shown, with the underlying percentage proportions unchanged. The colored bar normalizes only the reported rising/flat/falling totals; untraded constituents need not be counted. Missing breadth or value stays `—`, never inferred from the Top 200 stock sample. The VN-Index label and the new compact **Chart** button in the combined card header both open the existing realtime index chart modal (VNINDEX and VN30F1M futures); no extra chart stream is started by the card itself. The **ICT clock is displayed immediately after the VN-Index / VN30 card title in the header**, with a hover tooltip reporting `Thị trường: <trạng thái phiên>` and timezone. Its 15-second local clock refresh distinguishes pre-open, ATO, morning trading, lunch, afternoon, ATC, close and holidays/weekends without extra API calls; it indicates **market timetable**, not data-provider connection health. The old bottom session status row is removed.
- **Thanh khoản HOSE**: retains the live cumulative HOSE volume/GTGD source logic. An authenticated Finhay `list_indices(window=1D)` VNINDEX reading in VND takes precedence when it is from the current session. Otherwise only the provider-timestamped DNSE VNINDEX cumulative traded value/volume is eligible. The chart has a solid line for the current session. A dashed salmon line compares the **immediately previous Vietnam securities trading session only** (weekends and official holidays handled by the shared trading calendar), aligned with the solid current-day line by identical ICT minute-of-day. Both compact HOSE-liquidity and foreign-net charts render their 09:00–15:00 time ticks as **crisp, independently positioned HTML labels** in consistent 11px sans-serif, medium-weight tabular numerals; the SVG chart paths retain responsive stretching without distorting the hour glyphs. The HOSE chart has a zero-based cumulative value scale and pointer crosshair readouts showing each line at a selected trading minute; it never forward-extrapolates beyond the last real observation. Reference points must be **actual verified intraday observations captured on the same browser from the same source** (`finhay-vnindex` or `index-quote`), kept for at most three sessions in source-scoped storage. There is no provider intraday GTGD-history backfill: if the immediately previous session is missing or has fewer than two samples, explicitly show **Chưa ghi nhận phiên trước** and do not substitute an older session, full-day total, synthetic history or `volume × price` estimates.
- **Mua bán nước ngoài**: source selection remains Finhay authenticated full VNINDEX/HOSE or complete cumulative DNSE Top 200 foreign snapshot, while the visible **Top 200 partial** header text is removed. A card hover/source tooltip explicitly identifies DNSE Top 200 coverage (stock count and **not full HOSE**) whenever full Finhay flow is unavailable, preserving source transparency. Keep verified cumulative **Mua**, **Bán** and **Net** in the card text. The chart now plots **one signed, cumulative intraday net-buying line for the current Vietnam day only** (`net = buy − sell` from the same timestamped source snapshot, including real zero and negative values) with a visible zero reference and ICT minute ticks/crosshair; it does not overlay previous-session buy/sell lines. A previous-session retained snapshot must never appear as today before new-session quotes arrive. Foreign and liquidity sources may not mix; DNSE partial coverage stays **identifiable in card hover metadata** and must never be described as full HOSE. Existing recorded-sample storage remains source/day-scoped, optional and bounded; no new subscriptions or polling are introduced.
- **Tác động VNINDEX**: render only the provider's **five strongest positive and five strongest negative** finite `basketInfluence` entries, sharing a zero-axis and occupying a single no-scroll column of the top row. Positive bars sort strongest first on the left; negative bars sort weakest negative first, largest index drag at the right. The numeric contribution label for each **positive** stock is now anchored directly **above the shared zero/X-axis** at the lower edge of its green bar, rather than floating near the bar top; negative labels keep their previous placement. The previous separate, colored +/- aggregate bar was removed; its verified **five positive and five negative totals** now appear as compact green/red figures in the **card header**. This increases the actual stock bar chart height from **55px to 80px**, without changing the underlying 5+5 stocks or zero-axis normalization. Aggregate totals apply **only to the displayed ten entries**, not all VNINDEX constituents. The chart renders each contribution as a **high-contrast green/red point badge**, with a larger 10–11px bold signed numeric value but **without the redundant "điểm" text** under every stock column; the accessible description still specifies the point unit. Badges sit near the shared zero/X axis for easy comparisons, while stock tickers remain on the label row. Native hover/focus tooltip, help cursor and tooltip-only trading/foreign fields are intentionally removed; each contribution has an accessible screen-reader description without an interactive hover target. Values still come only from provider `basketInfluence`, not from inferred traded value, last price or volume. Worker index-impact WebSocket snapshots (original provider timestamp) take precedence when <=120s old; authenticated cached DNSE basket REST is the fallback. Realtime dot animations still require same-session freshness; lunch, EOD and stale-provider periods do not pulse. The bottom `LIVE / DNSE basketInfluence · timestamp` row remains removed. The final legend/source-caption rows are removed from both liquidity and foreign-net cards; the liquidity prior-session comparison date is retained in its upper row, and foreign scope (full HOSE versus Top 200 partial) remains in the card title tooltip and accessibility/source metadata.

**Market depth removed**: the former 11-bin HOSE Top 200 market-depth card, compute module, and its standalone test suite are retired; no depth calculation or subscriptions are run for market context. The market board's other realtime stock subscriptions and quote snapshot lifecycle remain unchanged.

The impact-only `/api/market/board-context` endpoint keeps its `market_board` authorization, 10-second live cache TTL, stale/retry safeguards and source-time checks; cache namespace advances to `market-board-context-v3` to exclude old chart history payloads. The Finhay market-context API remains separately authorized using `finhay_live` and Finhay OAuth, with 30-second polling. Browser storage is optional, bounded and stores no personal information.

## Browser realtime path

- DNSE WebSocket messages are queued and flushed on `requestAnimationFrame` instead of creating one React update per raw socket callback.
- Provider `mi` frames use `transactTime` and a same-session verified reference; cumulative foreign `f` frames use `multicastReceiveTime` and complete provider totals; `index-impact` frames keep DNSE's provider rows and source age. Strictly older source timestamps cannot replace browser state, while equal-time provider corrections are accepted.
- A 09:00/session reset clears index references, observed index points, impact state, and foreign-flow provenance. Generic quote receive timestamps do not qualify index volume or traded value as current provider data.
- Live quote/history writes go into detached ref-backed stores. A socket tick replaces only the affected symbol entry rather than cloning the full quote map.
- Visible quote state is committed to React at most every 250ms (`MARKET_UI_COMMIT_MS`), approximately 4Hz.
- VN30 and each raw industry column sort from a separate quote snapshot refreshed at most once per second (`MARKET_ORDERING_REFRESH_MS`). Price paint therefore does not force ranking/column sorting on every React commit.
- History updates replace only the affected ticker inside the ref-backed store and clone the outer history map at the next bounded UI commit.
- Compact priceboard rows and `LiveMoverCard` are memoized and only redraw when their visible quote/watch state changes. The compact rail has no mini charts; Top movers and the orderbook retain their existing history display.
- Mini-chart SVGs use the pre-regression pipeline: raw 5-minute history is hydrated without a second client-side time filter, while the current live price remains a fallback endpoint for symbols whose history provider is late. The ATO visibility gate remains separate and hides the entire chart until 09:15.
- Chart history stays bounded to the most recent display points.

The 250ms cadence is a UI paint policy, not a data-ingestion throttle. DNSE frames continue to be processed as they arrive; the browser merely publishes a bounded snapshot into React.

## GPU/compositing controls

The 2026-08-21 performance audit identified GPU compositing as a likely contributor to hot laptops:

- `.board-stock-row` previously used `transform: translateZ(0)`, which can promote roughly the full visible universe to persistent compositor layers. This forced promotion has been removed.
- The authenticated board page applies `market-board-performance.module.css`, which disables expensive `backdrop-filter` blur utilities inside the dense market-board surface while preserving the opaque glass-like backgrounds, borders, and shadows.
- Dense rows use `contain: layout style` to reduce unnecessary layout propagation without using `content-visibility`.
- Drop-shadow filters inside stock rows are suppressed on the performance surface.

Do **not** reintroduce `content-visibility` or naive row virtualization without redesigning the screenshot flow. QeoIndex captures the complete board DOM for screenshots; earlier visibility-based rendering shortcuts can omit off-screen industries from the exported image. Screenshot capture uses an isolated off-screen clone of the board, expands the horizontal industry rail and tallest column, and removes the clone in `finally`; it does not move the user's visible scroll position or saved column order.

## Price/reference rules

- Daily performance is anchored to the official/reference previous close, never to the session open.
- The initial SSR quote uses the best available live/snapshot/reference source in that order.
- DNSE 1-minute OHLC events are normalized into the board's 5-minute chart buckets.
- Price-unit normalization prevents feeds expressed in thousands from flattening VND-scaled histories.
- After close, cached intraday history and persisted snapshots keep prices/charts visible without labeling them as a live WebSocket tick.

## Trading-day UI lifecycle

- The browser evaluates session boundaries in `Asia/Ho_Chi_Minh`, including while the tab was opened before the session or temporarily hidden.
- At 09:00 on weekdays, the board atomically restores stocks and indexes to their reference values, clears session volume/foreign flow, provider provenance, impact state and chart state, reconnects realtime transport, and broadcasts a reset event to every open orderbook.
- Trading-date rollover is detected independently from UI phase transitions. If a suspended/throttled tab skips ATO and resumes later in the session, the board still resets exactly once for the new Vietnam trading day, reloads current-day intraday history, and reconciles fresh stock quotes/references through `/api/market/quotes`.
- The quote reconcile is session-guarded and preserves a newer realtime quote if one arrives while the request is in flight; its current-session reference may still update the baseline. The reconcile endpoint accepts a same-session snapshot as-is, but a snapshot from exactly the previous trading session is downgraded to a neutral previous-close fallback with zero session volume; older snapshots fail closed instead of carrying stale volume/reference/limit prices into the new day.
- Open orderbooks clear cached depth, matched trades, foreign flow, put-through rows, and chart history at the same boundary. In-flight Supabase/REST snapshots are ignored during ATO so yesterday's data cannot race back into the UI.
- Mini charts are deliberately blank from 09:00 through 09:14:59. DNSE 1-minute OHLC frames are accepted only from 09:15 through 14:29:59 and collapsed into one close per 5-minute bucket.
- During the 11:30–13:00 lunch break, realtime frames are ignored but the already-completed morning mini-chart remains visible through the 11:25 bucket. A fresh page load during lunch must hydrate that morning history rather than reuse an earlier partial-session cache.
- From 14:30 the live mini chart is frozen. At EOD availability (14:46 onward), the intraday snapshot is reloaded and may add the final 14:45 point once.
- The 09:00 notification is a bounded, opaque status alert with reduced-motion support; it does not add persistent blur or compositor-heavy animation.

## Layout contract

- `Bảng điện` is the default view on server render and for new users. It retains the original six grouped sector columns, 72px headers, per-ticker mini charts, and optional watchlist row.
- `Bảng ngành` is a separate explicit view in the same `LiveMarketBoard` instance. The selected view is stored per user after client hydration; switching views leaves the quote/history stores, subscriptions, orderbook handlers, and filter scope mounted once.
- The `Bảng điện` / `Bảng ngành` selector is the primary left-side control in the navigation row immediately below market context. Both tabs include icons and preserve the existing ARIA/keyboard tab behavior; watchlist/search/mode/filter controls remain on the right.
- Beside `Bảng ngành`, a per-user `Ẩn chỉ số` / `Hiện chỉ số` checkbox with up/down chevron collapses or restores the full market-context strip. Collapsing keeps `MarketContextStrip` mounted so current-session sampled liquidity/foreign mini-chart state and polling are preserved while the board workspace gains vertical space. The preference persists under a user-scoped local-storage key and defaults to visible.
- While `Bảng ngành` is selected, a second per-user `Ẩn Giá/KL` / `Hiện Giá/KL` checkbox sits beside the market-context control. Hidden mode removes both Price and Volume labels/values, keeps ticker and `+/-%`, and narrows every fixed/industry lane from 232px to 164px so smaller screens can show materially more columns. Switching the option does not reset quote/order/packing state and defaults to Price/KL visible.
- `Tất cả` and `Top movers` remain independent board modes. Search and Filter CP continue to scope the active ticker universe while either view is selected.
- The industry view uses a horizontally scrollable rail with fixed first columns `Theo dõi` and `VN30`, followed by deterministic vertical lanes of raw KFSP industry cards (falling back to the canonical sector label only when KFSP is blank). Contiguous small industries are packed into the same lane up to a bounded height budget, while large industries keep their own lane. Logical industry order remains the persisted drag/keyboard order; lane packing is derived and is never stored separately. It does not combine industries into the filter editor's six groups. The rail keeps extra right-side padding after the last lane so the final card is not flush against the viewport edge.
- Industry cards retain pointer dragging from anywhere on the header and keyboard reorder with the focused, tab-reachable header (Left/Right/Home/End). The decorative `⋮⋮` grip is removed to make room for full, non-truncated raw industry names, including in compact 164px mode. Headers keep the industry icon vertically centered beside the complete title + metrics block. All column headers — **Theo dõi**, **VN30**, and industry groups — now share the same vertically centered icon tile, two-line title and realtime metrics layout at a consistent 62px minimum height. The title font is **11px** (reduced from 12px). The metrics subline places `↑` rising / `-` unchanged / `↓` falling counts **first**, then the average valid-quote % change in a compact color-coded pill (green gain / red loss / neutral flat / muted unavailable). For the two fixed lanes, these metrics use the same valid-quote breadth and average rules as the industry lanes, scoped to the actual tracked/VN30 visible stocks respectively; when VN30 membership is unavailable, breadth and average remain unavailable rather than showing invented zero breadth. The metrics can wrap on narrow 164px columns without clipping the full title. Both average and counts use the same already-supplied `orderingQuotes`; missing/invalid prices or nonfinite change are tracked as unavailable and never mislabeled unchanged. The fixed headers remain non-draggable, preserving the watchlist search, VN30 partial coverage notice, and existing stock-row alignment. Per-user logical order is now **server-authoritative** in `user_preferences.settings.marketBoard.industryOrder` via the authenticated `GET/PUT /api/me/market-board-industry-order` endpoint, so a new device loads the same user order. The previous user-scoped `localStorage` key is retained only as a fast cache and offline fallback: on first load a customized legacy local order is migrated only if the server has no order; ordinary hydration does not write to the server, and every explicit drag/keyboard/reset operation persists sequentially. CAS on `updated_at` and nested-settings merge reduce accidental overwrites of other user settings. When a save fails, the UI offers retry instead of claiming sync succeeded. Newly discovered labels are appended, removed labels are dropped, and the two left anchors remain fixed. Reset restores securities, real estate, banks, then the remaining raw labels alphabetically. Reordering automatically repacks the derived lanes.
- Industry cards reuse the same `getSectorIcon()` mapping as Insights/Stock Identity instead of showing one generic chart icon for every industry. The compact layout keeps ticker/% values prominent while price is 11px and volume is 10px so long values stay inside the 232px row pill. Ticker rows use a 4px vertical gap for easier scanning. Hover strengthens the border/shadow and promotes the ticker from semibold to extra-bold without changing row dimensions or introducing layout jitter. Rows still sort valid current quotes first and then by percent change descending. They do not draw mini charts; the existing classic and Top movers rows keep their chart behavior.
- Industry row backgrounds use a neutral, very light grayscale for all changes in **[-1%, +1%]** (inclusive); exact **0%** is closest to the dark board surface rather than yellow. Beyond ±1%, direction colors return (green up, red down) and intensify symmetrically with `|changePercent|`, capped by 7% magnitude. Ceiling/floor colors still require actual provider limit prices matching the current price and remain distinct; no percentage-derived price limits are inferred. Missing or invalid quote values stay unavailable instead of being shown as zero.
- VN30 members come from DNSE's live basket-influence response rather than a hardcoded list. If membership is unavailable, the column stays in its anchored position and shows an unavailable state. Partial canonical coverage is shown explicitly; complete membership adds only source/time metadata to the header title so the quote rows stay aligned.
- The top market-context header has four responsive cards for VNINDEX, HOSE liquidity, VN30 and foreign flow (at wide widths). VNINDEX/VN30 show price/change with full-width mini charts, without redundant breadth or KL/GT rows. HOSE liquidity shows both cumulative GT (header) and same-session verified KL (subtitle). The second row is a height-matched compact 60% FireAnt-style signed contribution chart (red negative / green positive, largest negative at right) and 40% realtime HOSE market-depth histogram (11 signed percentage buckets). The histogram uses only covered current-session HOSE quotes within the subscribed Top 200 and explicitly discloses missing coverage; it does not claim to represent all 390-ish HOSE securities. Foreign and HOSE liquidity retain verified source/partial/unavailable labels. The duplicated lower KL/GT/breadth/foreign summary pills stay removed.
- Strong gainers use a static border highlight; permanent pulse animation is avoided.
- In `Bảng ngành`, the first `Theo dõi` column is always visible in the rail and **always has all four fields (Mã, Giá, +/-% and KL)** at the normal 232px width, even when the compact `Ẩn Giá/KL` mode is active for the other columns. - Filter CP reuses the same row/card components and does not introduce a second quote/history state store.
- Filter CP's KFSP sector editor keeps its six selection buckets and enforces mandatory/minimum-one selection rules locally; those editor buckets do not combine the raw industry columns in the priceboard.

## Current performance status

The structural state-machine optimization is now implemented in the focused `perf/market-board-state-buffer` change:

1. ref-backed quote/history stores avoid full-map clones for each socket tick;
2. React quote snapshots are bounded to ~4Hz instead of ~10Hz;
3. ranking plus classic sector/industry-column average snapshots refresh at ~1Hz;
4. redundant first-mount intraday bootstrap is skipped when SSR history coverage is sufficient;
5. Filter CP narrows DNSE stock subscriptions to only its resolved ticker set.

This materially reduces the maximum parent-board update opportunities and ranking recomputation frequency, but it is not a claim about a fixed CPU/temperature percentage. Actual gains depend on live market message volume, browser, device, open order-book windows, and whether DevTools/other tabs are active.

If production is still hot after this change, profile before adding more throttling. The next likely structural boundary would be splitting high-frequency quote paint from aggregate header statistics or moving individual rows to a subscription/store model. Do not jump directly to virtualization because the screenshot workflow requires the complete DOM.
